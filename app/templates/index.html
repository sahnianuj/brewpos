Brew POS Demo

A store register, two kitchen display screens (espresso bar + warming station), a pickup board, and a manager dashboard - each running its own local Couchbase Lite for JavaScript database in the browser, kept live by Capella App Services via channel-scoped replication. No polling: every screen updates the moment a synced write lands.

Open Register → Espresso KDS → Warming KDS → Pickup Board → Manager Dashboard →

Suggested demo flow

  1. Open Register, Espresso KDS, Warming KDS and Pickup Board in separate browser tabs (or windows, side by side) - each one is its own independent Couchbase Lite database and Replicator.
  2. On the Register, add a drink and a food item to a cart with a few customizations, then submit the order.
  3. Watch the drink line item appear live on the Espresso KDS and the food line item appear live on the Warming KDS - each only ever syncs its own station's channel (store-{id}-espresso / store-{id}-warming), so neither screen ever even receives the other's documents.
  4. Advance each line item through Start → Ready. Once every item on the order is ready, the whole order flips to READY and appears live on the Pickup Board (store-{id} channel).
  5. Mark it picked up on the Pickup Board, then check the Manager Dashboard for today's order volume and revenue.

Every write happens against the local Couchbase Lite database first, then replicates to Capella App Services in the background - the same architecture a real offline-capable register or KDS terminal would use. See sync-gateway/ for the channel design and sync functions, and app/static/js/cbl/ for the client code.

If a page shows an amber "App Services isn't configured" banner

That's expected until APP_SERVICES_URL, APP_SERVICES_USERNAME and APP_SERVICES_PASSWORD are set in .env (see sync-gateway/app-services-setup.md) and the app is restarted. Each page still works against its local, unsynced database in the meantime - it just won't see writes from other tabs until App Services is live.
